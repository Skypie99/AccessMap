## Changes made (committed to branch qa/auto-2026-05-22)

Listed in commit order. Each one re-ran `npm run typecheck` and stayed green.

### 1. fix: severityColor returns a safe gray for unexpected values — 50f059c
- Severity: low (defensive)
- File: src/screens/ReportFlagModal.tsx:245-256
- What was wrong: severityColor is a switch over FlagSeverity (1–5) with no
  default branch. If a row ever carries an out-of-range severity (dirty data,
  future schema widening), it returned undefined and the marker/severity-bar
  render breaks.
- What changed: Added `default: return '#999';` (neutral gray) with an inline
  comment.
- Why safe: Pure addition. Type system already exhausts cases 1–5, so no
  existing call site changes behavior — only runtime drift gets the gray
  fallback.

### 2. fix: cap listFlags to 500 rows — 97f94e7
- Severity: low today, medium at scale
- File: src/lib/flags.ts:51-67
- What was wrong: listFlags(...) selected every matching row. Fine at
  single-digit rowcount, ugly at thousands.
- What changed: Added .limit(500) and a JSDoc explaining the cap + pointing
  at proposal P1 for real pagination.
- Why safe: No signature change; 500 is well above current data volume.

### 3. fix: fail loudly in dev when Supabase env vars are missing — 4966e97
- Severity: developer-experience
- File: src/lib/supabase.ts:9-19
- What was wrong: Missing .env printed a console.warn and then every query
  silently 401'd. Confusing to debug.
- What changed: Kept the warn, added `if (__DEV__) throw new Error(message)`
  so the first screen you load tells you exactly what's wrong. Production
  behavior (no throw) unchanged so a misconfigured shipped build doesn't
  hard-crash.
- Why safe: __DEV__ is built-in to RN; the throw only fires when both env
  vars are missing, which is the "configured wrong locally" case.

### 4. fix: cancel the flash-banner timer on unmount — aa4da61
- Severity: minor leak
- File: src/screens/TasksScreen.tsx
- What was wrong: The "+points" banner used setTimeout to clear itself
  after 2.2s. If you tabbed away mid-flash, RN would warn about setting
  state on an unmounted component.
- What changed: Stored the timer id in a useRef; clear on each new flash
  and on component unmount via useEffect cleanup.
- Why safe: Standard React cleanup. Happy-path behavior identical.

### 5. fix: Tasks triage re-syncs with the server after each update — 8d57949
- Severity: low-medium (correctness)
- File: src/screens/TasksScreen.tsx
- What was wrong: setStatus did an optimistic local update from the
  existing flags array — but didn't re-fetch. If a concurrent triage on
  another device or a points-trigger failure caused divergence, the UI
  stayed wrong until manual pull-to-refresh.
- What changed: After updateFlagStatus succeeds, fire refresh() (background)
  on top of the optimistic update. Worst case: one extra network round trip.
- Why safe: Strict superset of previous behavior. Optimistic update gives
  instant feedback; refresh gives correctness.

### 6. fix: flash banner shows the correct points when you triage your own flag — 25ce0d5
- Severity: correctness (was actively misleading)
- File: src/screens/TasksScreen.tsx
- What was wrong: The flash always said "+2"/"+5" — the actor bonus. But
  when you triage your OWN flag, the trigger gives you the reporter bonus
  instead (+5/+10) and skips the actor bonus (see the auth.uid() <>
  new.user_id check in supabase/schema.sql:103). So the banner was lying
  when you acted on your own report.
- What changed: Added `isOwn = item.user_id === user?.id` and branch the
  flash message: "+5"/"+10" when own, "+2"/"+5" otherwise. Added a comment
  in setStatus pointing at schema.sql so future-you keeps them in sync.
- Why safe: No DB calls added. Read-only identity check.
- Note: I caught my own planning error here — the original plan said "+7/+15"
  (combined), which is wrong because the trigger explicitly skips the actor
  bonus when actor == reporter. Re-read the trigger before coding.

### 7. fix: guard setState in async loaders with a mountedRef — c7ba5e4
- Severity: low (defensive)
- Files: MapScreen, TasksScreen, ProfileScreen
- What was wrong: All three screens have useCallback async loaders that
  await a request then call setState. If the user navigates away during
  the request, the setState lands on a torn-down component.
- What changed: Added a mountedRef = useRef(true) plus an unmount-cleanup
  effect in each screen. Wrapped every post-await setState with
  `if (mountedRef.current)`.
- Why safe: Mounted-ref is a beginner-readable React pattern. If the guard
  is wrong, the worst case is a discarded result — never broken state.
- Note: I considered splitting into three commits (one per file) but kept
  it as one because the change is identical mechanically and conceptually.
  Easy to split if you'd rather review each in isolation.

### 8. chore: drop unused extra block from app.json — fef8cd0
- Severity: cleanup
- File: app.json
- What was wrong: "extra": { "supabaseUrl": "", "supabaseAnonKey": "" } was
  dead config — nothing in the codebase reads Constants.expoConfig.extra.
  Misleading for a future contributor.
- What changed: Deleted the block (and the trailing comma).
- Why safe: Verified no consumers across the 12 source files.

### 9. fix: SignInScreen — basic validation + check-your-email hint — 174046c
- Severity: UX
- File: src/screens/SignInScreen.tsx
- What was wrong: Empty / malformed input silently hit Supabase and bounced
  back as the unhelpful "Invalid login credentials". After successful
  sign-up, the screen sat blank — no idea what to do next.
- What changed:
  - Trim + lowercase the email before submitting.
  - Block submit if email lacks "@" or password is under 6 chars; show an
    inline accessible <Text> with the error (uses
    accessibilityLiveRegion="polite").
  - After successful sign-up, show a "Check your email" Alert naming the
    address.
  - Added autoComplete + textContentType so iOS/Android password managers
    can fill/save.
- Why safe: No new screens, no new flows, no new deps. Only stops bad input
  from reaching Supabase and shows a sensible message.
- Skipped intentionally: password reset — that needs deep-link config and a
  new screen. Tracked as P3.

### 10. a11y: label every button and image for screen readers — 15f2eb0
- Severity: mission-critical (this app is literally about accessibility)
- Files: MapScreen, TasksScreen, ReportFlagModal, ProfileScreen
- What was wrong: Most Pressables had no accessibilityRole; many lacked
  accessibilityLabel. Photo <Image> elements had no alt. Screen-reader
  users would hear "button" announced inconsistently and have no idea what
  photos depicted.
- What changed:
  - accessibilityRole="button" on every Pressable (filter chips, severity
    pills, FAB, card actions, photo controls, sign out, cancel/submit).
  - accessibilityLabel on every touchable that lacked one.
  - accessibilityLabel on every photo <Image> (callout + Tasks thumbnail +
    report preview), describing the depicted issue.
  - accessibilityState where applicable: selected on active filter chips/
    severity pills, disabled + busy on the submit button, disabled on the
    Report FAB when location isn't ready, expanded on the filter toggle.
  - accessibilityHint on the Report FAB and Tasks card.
- Why safe: Purely additive — no visual changes, no behavior changes.

## Proposals (NOT applied — need your review)

These are the high-blast-radius items the QA workflow won't auto-apply:
schema/RLS, dependency installs, auth/security config, and large refactors.
Each one is a write-up you can grab when you have time.

### P1 — Cursor pagination + viewport-clipping for listFlags
- Why it matters: Tonight's .limit(500) is just a floor. As you accumulate
  flags, TasksScreen will start loading a wall of cards, and MapScreen will
  draw a wall of pins far outside the viewport.
- Exact steps:
  1. In src/lib/flags.ts, change the signature to
     listFlags(statuses, opts?: { limit?: number; before?: string }) where
     `before` is a created_at cursor.
  2. In TasksScreen, add onEndReached/onEndReachedThreshold to the FlatList,
     track a loadingMore state, append on success.
  3. In MapScreen, switch to a viewport-bounding query: pass region
     (lat/lng deltas) into listFlags and add .gte('lat', ...) etc. Re-query
     on onRegionChangeComplete.
- Risk/blast radius: Medium. Filter logic (activeCategories, minSeverity)
  should eventually move server-side too, but that's a follow-on.

### P2 — Wrap auth.uid() in RLS policies + enable leaked-password protection
- Why it matters: Supabase Advisor flags 4 auth_rls_initplan warnings —
  every `auth.uid() = …` in a policy re-evaluates per row, which gets slow
  at scale. The fix is purely a perf optimization (semantics identical).
  Separately, leaked-password protection isn't enabled, so users can choose
  breached passwords.
- Exact steps (Supabase Dashboard → SQL Editor):
  1. Open supabase/schema.sql. Replace `auth.uid() = …` with
     `(select auth.uid()) = …` in the four public.users / public.flags
     policies, and
     `(storage.foldername(name))[1] = (select auth.uid()::text)` in the
     two Storage policies. Save the new file back.
  2. Run the updated schema.sql via the SQL Editor — `create policy` lines
     are idempotent via the matching `drop policy if exists` clauses
     already in the file.
  3. Dashboard → Authentication → Policies → toggle on "Check passwords
     against HaveIBeenPwned".
  4. Re-run Database → Advisors and confirm the four auth_rls_initplan
     warnings are cleared.
- Risk/blast radius: Low for (1) (perf only). Medium for (3) (existing
  users with weak passwords are prompted on next change; some may complain).

### P3 — Password reset + email-confirmation flow in SignInScreen
- Why it matters: Tonight's commit added a "check your email" alert after
  sign-up, but you still have no way to recover a forgotten password.
- Exact steps:
  1. Add a `linking` config to RootNavigator listing the accessmap://
     scheme that's already in app.json.
  2. Create src/screens/ResetPasswordScreen.tsx that calls
     supabase.auth.resetPasswordForEmail(email, { redirectTo: 'accessmap://reset' }).
  3. Add a "Forgot password?" link to SignInScreen that navigates to the
     new screen.
  4. In Supabase Dashboard → Auth → Email Templates → Reset Password →
     change the {{ .ConfirmationURL }} to use the accessmap://reset
     redirect.
- Risk/blast radius: Medium. Deep links are easy to misconfigure and break
  sign-in if you typo the scheme.

### P4 — Marker clustering for PlatformMap
- Why it matters: Beyond ~50 markers in a viewport, pan/zoom on both native
  and web starts to feel sluggish. Clustering keeps the map interactive at
  high density.
- Exact steps:
  1. npm install --legacy-peer-deps react-native-map-clustering supercluster
     (the --legacy-peer-deps flag is mandatory — see CLAUDE.md gotcha #2).
  2. Wrap the native MapView in PlatformMap.tsx with
     react-native-map-clustering's ClusteredMapView (drop-in API).
  3. In PlatformMap.web.tsx, implement clustering manually with
     supercluster — react-leaflet has no clustering primitive.
  4. Threshold: cluster when more than ~50 markers in viewport.
- Risk/blast radius: Medium-high. The clustering layer can break the
  existing showCallout(id) ref method when the target marker is collapsed
  into a cluster — needs a "zoom into cluster, then show callout" fallback.

### P5 — Shared FlagsProvider to dedupe Map ↔ Tasks fetches
- Why it matters: Map and Tasks each fetch listFlags(['open', 'verified'])
  independently. Tonight's commits #5 and #7 only made the duplication
  more visible.
- Exact steps:
  1. Create src/lib/flagsStore.tsx exporting a FlagsProvider and useFlags()
     hook with { flags, refresh, loading, error }.
  2. Wrap RootNavigator in <FlagsProvider>.
  3. Replace useState<FlagRow[]>([]) + refresh in MapScreen and TasksScreen
     with useFlags().
  4. Have createFlag and updateFlagStatus callers invoke refresh from the
     store after success.
- Risk/blast radius: Low-medium. Mechanical refactor but touches 3+ files;
  do it while you have the time to verify all the fetch sites.

### P6 — Image resize / thumbnail pipeline
- Why it matters: expo-image-picker is called with quality: 0.7 but no max
  dimensions. A 4032×3024 photo straight from a modern phone is 3-5 MB.
- Exact steps:
  1. npm install --legacy-peer-deps expo-image-manipulator
  2. In src/lib/flags.ts, update uploadFlagPhoto to first call
     ImageManipulator.manipulateAsync(localUri, [{ resize: { width: 1600 } }], { compress: 0.6, format: SaveFormat.JPEG }).
  3. Optionally also upload <userId>/<ts>-thumb.jpg at 400px for list
     views; render thumbnails from the thumb URL.
- Risk/blast radius: Low. Path scheme unchanged so RLS policies still apply.

### P7 — Enable noUncheckedIndexedAccess
- Why it matters: A strict-TS flag that catches "array access returns T but
  the index might not exist" bugs at compile time. Cheap, bounded fix.
- Exact steps:
  1. In tsconfig.json, add "noUncheckedIndexedAccess": true.
  2. Run npm run typecheck — expect 3–5 errors. Likely candidates: match?.[1]
     in flags.ts (already guarded), result.assets[0]?.uri in
     ReportFlagModal (already guarded), possibly some Array<…>[i] in styles
     or maps.
  3. Fix each with ?? fallback or an explicit if (!x) guard.
- Risk/blast radius: Low. Bounded, mechanical fixes.

### P8 — ESLint + Prettier + GitHub Actions typecheck workflow
- Why it matters: npm run typecheck is the only safety net today. Lint
  catches a different class of bugs (missed deps in useEffect, unused vars,
  accessibility patterns). CI catches "I forgot to typecheck before pushing".
- Exact steps:
  1. npm install --save-dev --legacy-peer-deps eslint @react-native/eslint-config prettier
  2. Add a flat-config eslint.config.js extending @react-native/eslint-config
     plus rules @typescript-eslint/no-unused-vars: warn and
     react-hooks/exhaustive-deps: warn.
  3. Add a .prettierrc matching the existing style:
     { "singleQuote": true, "semi": true, "tabWidth": 2,
       "trailingComma": "all", "printWidth": 90 }
  4. Add scripts to package.json: "lint": "eslint .",
     "format": "prettier --write .", "format:check": "prettier --check .".
  5. Push the repo to GitHub, then add .github/workflows/ci.yml with two
     jobs: typecheck (runs npm ci --legacy-peer-deps then npm run typecheck)
     and lint (same install, runs lint + format:check).
- Risk/blast radius: Medium — lint will surface ~20–50 nits that need a
  follow-up cleanup PR. Worth it.
