## Per-feature

### F1 — Map empty-state card (commit `2201be1`)

**What shipped:** When the user's active filters return zero flags, a floating card appears centered on the Map: "No flags match your filters / Try broadening your filters, or reset to see all nearby flags." A 🔍 icon, body copy, and a "Reset filters" button (one-tap → `clearFilters()`, the same handler the panel's Clear link uses).

**How to see it:** Open the app → Map tab → open the filter panel → check Categories you know are rare in your area (or set Min Severity to 5). Card appears within a render tick. Tap "Reset filters" to dismiss.

**Born accessible:**
- `accessibilityRole="alert"` + `accessibilityLiveRegion="polite"` on the card (Android narrates appearance automatically).
- One-shot `AccessibilityInfo.announceForAccessibility()` on the false→true transition (iOS), gated by a `useRef` so re-renders in the empty state don't re-speak.
- Reset button: `minHeight: 44`, label + hint that spell the action.
- Icon paired with explicit text — never color-alone.

**Refine vs. remove:** Keep. This is a clear UX gap fix.

**Proposed follow-up:** none.

### F2 — Collapsible filter panel (commit `e53a449`)

**What shipped:** Filter panel header gets a `▾` / `▸` chevron. Tap to collapse everything below the title (Saved + Categories + Severity + Status). State persists across launches via a new tiny module `src/lib/filterPanelPrefs.ts` (device-wide key `@accessmap/filter_panel_collapsed_v1` — separate file per the two-key LEARNINGS, since this is a UI shape preference not tied to filter values).

**How to see it:** Map → tap the ⌕ filter button to open the panel → tap "Filter flags" title or the chevron. Sections collapse with the panel showing just the title row (Clear link still works when collapsed). Reload the app — state persists.

**Born accessible:**
- Chevron Pressable: `accessibilityRole="button"`, `accessibilityState.expanded`, label spells the action (`Expand filter panel` / `Collapse filter panel`), hint describes the consequence.
- Chevron glyph itself is hidden from AT (`accessibilityElementsHidden`) so screen readers don't read "▾" literally.
- Hit slop 8 + 32pt row + parent padding ≈ 44pt tap area.

**Refine vs. remove:** Keep. Useful on small screens.

**Proposed follow-up:** consider animating the height transition (currently snaps). Not a blocker.

### F3 — Severity quick-cycle button (commit `774c08f`)

**What shipped:** A new "{n}+" button in the top icon row, between the filter toggle and the refresh button. Tap to cycle `1+ → 2+ → 3+ → 4+ → 5+ → 1+`. Background tints to that severity's color (green/yellow/orange/red) when `minSeverity > 1`; stays neutral white at `1+` (the "no filter" state).

**How to see it:** Map → tap the new "1+" button repeatedly. Watch the marker set narrow as you cycle up. Screen reader users hear the threshold spoken on every tap.

**Born accessible:**
- Label spells the current state in words (`Minimum severity: Moderate and above`) using `SEVERITY_LABELS` from `flags.ts` — never relies on the visible "3+" glyph.
- `AccessibilityInfo.announceForAccessibility` on every change.
- Color always paired with a number, never the only signal.

**Refine vs. remove:** Keep. The cycle is fast and visible.

**Proposed follow-up:** the button is 44×36 — wider than the existing round 36×36 icon buttons. If Dani wants strict consistency with the round style, swap to a 36×36 with smaller text or a different glyph. Not urgent.

### F4 — Share a flag (commit `533fa12`)

**What shipped:** Share button next to "View on Map" in the Flag Detail modal. Native iOS/Android opens the OS share sheet via React Native's `Share` API. Web tries `navigator.share` → falls back to `navigator.clipboard.writeText` → falls back to a plain `Alert` with the text. Message format:

```
Curb cut missing flag on AccessMap
Severity 3/5 (Moderate) at 37.77490, -122.41940

accessmap://flag/<id>
```

The `accessmap://` scheme already matches `app.json`. The in-app handler for `accessmap://flag/*` is **not wired yet** — tapping such a link today just opens AccessMap to its last screen. Added to `FEATURES.md` "Next" tier as a small follow-up using `expo-linking`.

**How to see it:** Tasks tab → tap any flag card → tap the new "Share" button next to "View on Map". On native: OS share sheet. On web: browser share dialog or "Link copied" alert.

**Born accessible:** label + hint on the share button; `accessibilityState.disabled` mirrors the existing `busy` guard so AT users hear it disabled during a status change.

**Refine vs. remove:** Keep — but the value isn't fully there until the deep-link handler is wired. Today the link is informational (recipient sees the coords and can open the app); tomorrow it should land them on the flag.

**Proposed follow-up (small):** add `expo-linking` listener in `App.tsx` that parses `accessmap://flag/{id}`, fetches the flag, navigates to Map with the existing `{focusFlag: { id, lat, lng }}` route param.
