## What shipped this sprint

### F5 — Watched Flags
**Branch:** `feat/watched-flags-2026-05-23` → merged to main

A user can now "watch" any flag to track its status over time.

**Detail modal (FlagDetailModal.tsx):**
- New star pill button (`☆ Watch` / `★ Watching`) appears above the secondaryRow once the user's watched list has loaded from AsyncStorage (hidden while loading to prevent a flash of wrong state).
- Neutral outline border when unwatched → amber filled when actively watching.
- `accessibilityState.busy` set while the AsyncStorage write is in flight so screen readers announce "loading" during save.

**Storage layer (src/lib/watchedFlags.ts — new file):**
- Per-user AsyncStorage keyed as `@accessmap/watched_flags_v1:{userId}` — two-user-safe.
- `loadWatched`, `addWatched`, `removeWatched` helpers. Idempotent on duplicates.
- MAX_WATCHED = 200; FIFO drop on overflow (oldest entry removed).
- Defensive parser: invalid JSON / non-array / mixed-type arrays all degrade to `[]`.

**Batch fetch (src/lib/flags.ts):**
- `fetchFlagsByIds(ids: string[]): Promise<FlagRow[]>` — single `.in('id', ids)` query. Returns `[]` for empty input (skips the round-trip). Missing IDs (deleted flags) are silently dropped by Supabase — the caller handles the count mismatch.

**Watched Flags list (src/components/MyWatchedModal.tsx — new file):**
- Bottom-sheet modal accessible from Profile → "Watched Flags" card row.
- Flags sorted: open/verified first (still need attention), resolved/rejected last (done).
- Each row: severity dot + category label + date + status badge + amber ★ unwatch button.
- Optimistic unwatch: row disappears immediately; AsyncStorage write is fire-and-forget.
- If some watched IDs are missing (flags deleted), a banner announces the count.
- Empty state, error state, retry button, loading spinner all covered.

**ProfileScreen.tsx changes:**
- New "Watched Flags" card row between My Reports and My Feedback.
- `watchedOpen` / `watchedRefreshKey` states added.
- `flagDetailSource: 'reports' | 'watched' | null` tracks which list modal opened the current FlagDetailModal, so `handleDetailClose` reopens the right one.

**Tests:** 17 new tests in `src/lib/__tests__/watchedFlags.test.ts` covering load/add/remove, idempotency, FIFO cap, parse robustness, and per-user isolation.

### F6 — Category Quick-Cycle Button
**Branch:** `feat/category-quick-cycle-2026-05-23` → merged to main

A new button in the Map top action bar lets the user quickly scope the map to one category type without opening the full filter panel.

**Placement:** between the severity (N+) and refresh (⟳) buttons.  
**Sequence:** All → No ramp → Broken sidewalk → Blocked path → Missing signal → Steep grade → Other → All

**Behaviour:**
- Shows `⊕` (circled-plus, suggesting "all/expand") when all categories are visible.
- Shows the CATEGORY_ICONS glyph for the active category when filtered to one.
- Fills brand-blue (#2f80ed) and applies `iconTextActive` when a solo category is selected — same active treatment as the severity and filter buttons.
- When multiple categories are set via the full filter panel, the next tap treats the state as "All" and advances to No Ramp (the first single-category view).
- Announces the new filter to screen readers on each tap via `AccessibilityInfo.announceForAccessibility`.

**Implementation notes:**
- `CATEGORY_CYCLE: Array<FlagCategory | null>` is defined at module level (outside the component) so `cycleCategory`'s `useCallback` deps array can be empty [].
- All TypeScript type narrowing done without `!` non-null assertions — uses `([...prev] as FlagCategory[])[0] ?? null` and conditional guards.
- No new files, no new tests — the logic is trivial (Set mutation + a fixed array index) and covered by the existing `mapFilters.test.ts` behavioural patterns.
