## Feature 1: Tasks Tab Badge

### Spec (as built)

**What:** The Tasks bottom-tab icon shows a live numeric badge with the count of
currently-loaded `'open'` flags. Badge is cleared (no badge shown) when there are zero
open flags, giving users a satisfying "queue empty" state.

**Where it lives:** `src/navigation/RootNavigator.tsx` — the `NavInner` component that
owns the Tab.Navigator. Badge is passed via the `tabBarBadge` option on the Tasks tab.

**User flow:**
1. User opens app — if there are open flags, the Tasks icon shows a number badge (e.g. "7").
2. User goes to Tasks and verifies/resolves flags — badge decreases as flags are triaged
   (via FlagsProvider's optimistic updates).
3. When no open flags remain, badge disappears entirely.

**Components/data:** `useFlags()` is called in `NavInner` (already inside `FlagsProvider`).
`openCount = flags.filter(f => f.status === 'open').length`. Capped at 99.

**Accessibility:** React Navigation automatically incorporates the badge count into the
tab's `accessibilityLabel` (e.g., "Tasks, 7 unread items"). Both VoiceOver (iOS) and
TalkBack (Android) announce it.

**Assumptions:** Shows total open flags loaded in the provider (not per-user). This is the
right signal — all open flags represent community work waiting to be done.

### How to try it

1. Run the app (`npm start` or `npm run web`).
2. Sign in.
3. If there are open flags loaded, look at the bottom tab bar — the "✅ Tasks" tab will
   show a blue badge with the open-flag count.
4. Go to Tasks, verify a flag → badge decrements.
5. Triage all open flags → badge disappears.

## Feature 2: High-Severity Photo Nudge

### Spec (as built)

**What:** In the "Report a Flag" modal, when a user selects severity 4 (Major) or 5
(Severe/impassable) without yet attaching a photo, an amber-tinted tip card appears
between the "Photo (optional)" label and the photo picker buttons.

Text: *"A photo helps verify this [major/severe] barrier without a site visit."*

The card disappears as soon as a photo is attached — no persistent clutter.

**Where it lives:** `src/screens/ReportFlagModal.tsx`, just after the `<Text style={styles.label}>Photo (optional)</Text>` line.

**User flow:**
1. User opens the report modal.
2. User selects severity 1–3 → no nudge (normal flow).
3. User selects severity 4 or 5 → amber tip card appears below the photo label.
4. Screen reader users hear the tip announced once (iOS VoiceOver via
   `AccessibilityInfo.announceForAccessibility`; Android TalkBack via
   `accessibilityLiveRegion="polite"`).
5. User attaches a photo → tip card disappears.
6. User removes photo → tip re-appears if severity is still ≥4.

**Components/data:** No new files. Uses existing `severity` and `photoUri` state. Pure
rendering logic.

**Accessibility:**
- Full `accessibilityLabel` on the nudge container (merged into one AT element via
  `accessible={true}`).
- `accessibilityLiveRegion="polite"` for Android live announcement.
- `useEffect` + `prevHighRef` pattern for iOS VoiceOver one-shot announcement when
  severity first crosses into ≥4 territory.
- Emoji is hidden from AT tree (`accessibilityElementsHidden`).
- Contrast: `warningBg #fff7e6` / `warningFg #714b00` = 8.3:1, WCAG AA.

**Assumptions:** Severity thresholds (≥4 = "high") match existing `SEVERITY_LABELS`
("Major" at 4, "Severe/impassable" at 5). No persistent storage needed — ephemeral
nudge within a single modal session.

### How to try it

1. Run the app (`npm start`), sign in, tap the ✚ Report FAB on the map (or long-press
   the map and confirm).
2. In the Report modal, tap severity 1, 2, or 3 → no nudge under "Photo (optional)".
3. Tap severity 4 or 5 → amber tip card appears: "A photo helps verify this major/severe
   barrier without a site visit."
4. Tap "📷 Take photo" or "🖼 Choose from library" and select a photo → tip disappears.
5. Remove the photo (✕) → tip re-appears.
6. (Optional, iOS) Enable VoiceOver, focus the severity picker, change to 4 → hear the
   announcement.
