## Findings & Fixes

### 1. PhotoGallery (`src/components/PhotoGallery.tsx`)

| # | Issue | Severity | Fix |
|---|-------|----------|-----|
| 1.1 | Thumbnails had no `accessibilityLabel` / `accessibilityRole` — screen reader announced nothing or just "image". | High | Each thumbnail `Pressable` → `accessibilityRole="imagebutton"`, `accessibilityLabel="Photo N of M"`, hint "Opens the full-screen photo viewer". Inner `Image` set `accessible={false}` + `importantForAccessibility="no"` so it doesn't double-announce. |
| 1.2 | Lightbox modal not announced as modal; full image unlabeled; page counter ("1 / 3") was visual-only, not announced. | High | Backdrop `Pressable` → `accessibilityViewIsModal` (traps SR focus), `accessibilityRole="button"`, `accessibilityLabel="Photo N of M, full screen"` (this **announces the page counter**), hint "Double tap to close". Image + visual counter hidden from SR (`importantForAccessibility="no"` / `"no-hide-descendants"`) to avoid duplicate reading. |
| 1.3 | Dismissal via screen reader. | — | Already covered: `Modal onRequestClose` (Android back / SR dismiss) was wired, and the backdrop is now a labelled, activatable Close button. |
| 1.4 | Empty state ("No photos") not announced meaningfully. | Low | Wrapper `View` → `accessible`, `accessibilityRole="text"`, `accessibilityLabel="No photos attached to this report"`. |

**Swipe-gesture alternative:** This gallery has **no swipe gesture** — the
lightbox shows the tapped photo, and you dismiss it and tap another thumbnail to
view a different one. That tap-thumbnail flow is already fully operable by
VoiceOver/TalkBack, so no non-swipe alternative needed to be added.

### 2. Comments (`src/screens/MapScreen.tsx` → `CommentsSection`)

| # | Issue | Severity | Fix |
|---|-------|----------|-----|
| 2.1 | Comment list had no list semantics; author and body were two separate SR nodes per comment. | Medium | `FlatList` → `accessibilityRole="list"`. Each row's content `View` grouped into one node: `accessible`, `accessibilityRole="text"`, `accessibilityLabel="Comment by {author}: {body}"`. |
| 2.2 | Delete button labelled only "✕" — SR read nothing useful. | High | `accessibilityRole="button"`, `accessibilityLabel="Delete {author}'s comment"`, hint "Removes this comment permanently". (Delete kept as a **separate** focusable node from the comment text so it stays operable.) |
| 2.3 | Send button: disabled/busy state not announced; no role/label. | High | `accessibilityRole="button"`, `accessibilityLabel` = "Send comment" / "Sending comment", `accessibilityState={{ disabled, busy }}`. |
| 2.4 | Loading + error states not announced. | High | `ActivityIndicator` → `accessibilityLabel="Loading comments"`. Error `Text` → `accessibilityRole="alert"` + `accessibilityLiveRegion="assertive"`. Empty state → `accessibilityLiveRegion="polite"`. |
| 2.5 | Comment `TextInput` relied on placeholder for its name (placeholders aren't reliable SR labels). | Medium | Added `accessibilityLabel="Add a comment"`. |
| 2.6 | Heading "Comments" not a header. | Low | `accessibilityRole="header"`. |

**Character counter:** There is **no visible character counter** (the input
silently caps at `MAX_COMMENT_LENGTH = 500`). Nothing to announce; no counter
added (avoiding unrequested scope).

### 3. Multi-photo picker (`src/screens/ReportFlagModal.tsx`)

| # | Issue | Severity | Fix |
|---|-------|----------|-----|
| 3.1 | **Web has no way to add a photo and no keyboard path** — `pickPhoto` calls `Alert.alert` with buttons, which is effectively a no-op on react-native-web. | High (functional + a11y) | On `Platform.OS === 'web'`, skip the native action sheet and go straight to the library/file picker (`addPhoto(false)`) — the OS file dialog is keyboard-accessible. Native still gets the Camera/Library/Cancel sheet. |
| 3.2 | "Remove photo" control was an unlabeled "✕". | High | `accessibilityRole="button"`, `accessibilityLabel="Remove photo N"`, plus `hitSlop={8}` for a comfortable target. |
| 3.3 | "Add" button had no role and no count context for SR. | Medium | `accessibilityRole="button"`, `accessibilityLabel="Add photo, N of 5 added"`, hint "Opens the camera or photo library". Decorative "＋"/"Add" text marked `importantForAccessibility="no"`. |
| 3.4 | Photo thumbnails unlabeled. | Low | `accessibilityRole="image"`, `accessibilityLabel="Photo N of M"`. |
