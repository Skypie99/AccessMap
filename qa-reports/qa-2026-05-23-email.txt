================================================================
THE ONE THING TO ACT ON
================================================================

There is a HIGH-severity hidden bug in the moderation flow:

  - supabase/schema.sql:157-162 says "only the flag owner can update
    a flag" (the RLS policy "flags update own").
  - But supabase/schema.sql:103-108 (the points trigger) and the
    Tasks-screen UI both assume any authenticated user can triage
    any flag.

Net effect: triaging your OWN flag works. Triaging anyone ELSE's
flag will silently fail with an RLS error. You don't see this in
single-account dev testing; you'll see it the second a second user
signs up.

Fix is propose-only (RLS is high-blast-radius). Two paths:

  P-NEW-1 (faster band-aid): add a second UPDATE policy that lets
          any authenticated user update ONLY the status column.
          ~15 lines of SQL, fully reversible.

  P-NEW-3 (better long-term): replace the trigger with a
          SECURITY DEFINER RPC `set_flag_status(...)` that does
          its own auth check and returns the awarded points.
          Touches schema + 2 client files; save for a dedicated
          session.

Apply one of them BEFORE letting anyone other than you sign up.
Exact SQL + smoke-test steps are in the full report.
