1) Profile editing — display name + default tab + show intro again
   Branch: feat/profile-edit-2026-05-23
           (stacked on feat/onboarding-cards-2026-05-23 — merge that first)
   Commit: a849a56  ProfileScreen: editable display name, default tab,

   Files:  +370 / -9 against the onboarding-cards base
           (new src/lib/preferences.ts, src/lib/users.ts; updates to
           onboarding.ts, RootNavigator.tsx, App.tsx, ProfileScreen.tsx)

   Three new sections in Profile:
     - Display name: TextInput + Save. Writes display_name on
       public.users (existing column — no schema change). Empty
       persists as NULL.
     - Default landing tab: 3 segmented pills (Map / Tasks /
       Profile), per-user AsyncStorage. Drives RootNavigator's new
       initialRouteName prop. App.tsx holds first render until the
       preference is in hand, so there's no Map→Tasks flash.
     - Show me the intro again: link + confirm dialog → clears the
       onboarding seen key → next sign-in re-shows the 3-card intro.
   Each section header uses accessibilityRole="header" so screen-
   reader users can jump straight to a control. Success actions
   announce via AccessibilityInfo.announceForAccessibility.

2) Reporter-side points toast
   Branch: feat/reporter-points-toast-2026-05-23  (off main, independent)
   Commit: a93091a  Reporter points toast — "+N points while you were away"
   Files:  +234 / -2 (new src/lib/points.ts, src/components/FlashBanner.tsx
           + App.tsx)

   When the app launches signed in, fetches current public.users.points
   and compares with a per-user AsyncStorage watermark. If higher,
   raises a green floating banner: "You earned +N points while you
   were away!" — auto-dismiss after 4s, tap-to-dismiss, announced via
   accessibilityLiveRegion + announceForAccessibility. First-ever
   observation is silent so we don't celebrate pre-existing points.
   Singular/plural copy ("+1 point" vs "+N points") for natural
   screen-reader reads. The FlashBanner component is generic
   (message/onDismiss/tone/durationMs) so future confirmation toasts
   reuse it.

   Deliberately a launch-time check, not Supabase Realtime — opening
   the supabase_realtime publication on a new table is a schema/
   dashboard change (propose-only per the skill). Realtime upgrade
   plan included in the full report; the toast surface stays the same.
