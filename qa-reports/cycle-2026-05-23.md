# The Proposed Loop Structure — "the green cycle"

A cycle is the smallest reversible unit of forward motion. Each one ships 3 features (or runs an "audit" pass), green-gated all the way through, with one Morgan briefing at the close. The loop is **self-correcting** (Orion handles failures locally), **self-paced** (no fixed clock), and **self-terminating** (clear "where we need to be" criteria).

## Definition of "where it needs to be"

We stop running the green cycle (or switch to audit-only mode) when ALL of:

1. FEATURES.md "Now" tier is empty.
2. Zero open critical or major QA findings across the most recent qa-reports.
3. All proposed migrations are EITHER applied OR formally deferred with a dated rationale in DECISIONS FOR SKY.
4. Unmerged branch count is ≤ 3 active feature branches (the in-flight cycle's work).
5. LEARNINGS.md has been re-distilled at least once since the last "now" item closed (consolidation pass).

## The six phases

**Phase 1 — BUILD (Shamus, in parallel on 3 branches)**
- Pick the top 3 from FEATURES.md "Now" tier (or "Next" if Now is empty).
- Each on a `feat/<slug>-YYYY-MM-DD` branch off `main`.
- Pattern: pure lib in `src/lib/` + tests + UI wiring.
- Born accessible (WCAG 2.2 AA floor; 44pt targets; labels/roles/states/contrast).
- Commit-by-commit green: `npx tsc --noEmit && npx jest` must pass after every commit.
- Output: 3 green feature branches.

**Phase 2 — SELF-CORRECT (Orion, only when triggered)**
- Triggered ONLY when Phase 1 hits FAIL_FAST (gates red, conflict, unexpected scope creep).
- Up to 3 local recovery attempts (refactor → simplify → back out → retry).
- Const. 8.5 safe-recovery boundaries: no protected paths, no secrets, no live DB, no remote.
- Attempt 4 → produce BLOCKER ESCALATION PACKAGE → Morgan picks up → Sky decides.
- Output: green branch OR escalation package (never a half-built feature pretending to be done).

**Phase 3 — CLEAN (Alex, parallel with Phase 4)**
- Runs on each feature branch BEFORE QA touches it.
- Targets: dead state, unused imports, stale comments, redundant prop drilling, missing `accessible={true}` where Views collapse children, missing `accessibilityViewIsModal` on modal cards.
- Branch-hygiene scan: flag any worktrees > 24h old AND > 2 commits behind main with no LEARNINGS reference.
- Output: cleanup commits (squashed or appended) + a stale-branch list for Morgan's briefing.

**Phase 4 — TEST (Gary, parallel with Phase 3)**
- Lint pass on diffs (no `any`-cast leak, no Promise misses, no `react-leaflet` import outside `.web.tsx`).
- Coverage check on new pure libs: every exported function has at least one positive + one negative test.
- Full regression: `npx jest` on the branch → must be green.
- Output: test additions (PRs into the same feature branch) + a green/red status per branch.

**Phase 5 — FIX (Quinn → Shamus polish loops)**
- Quinn launches 3 concurrent QA agents in parallel:
  - **Pass 1 — broad correctness** (state machines, closures, races, ignored errors)
  - **Pass 2 — accessibility** (WCAG 2.2 AA — touch targets, roles, states, decorative-hiding, modal traps, live regions, contrast)
  - **Pass 3 — edge cases** (Unicode, user-swap, concurrent ops, empty states, limits, backward compat, lifecycle)
- Findings consolidated to `qa-reports/qa-<feature-set>-YYYY-MM-DD.md` with per-finding severity (Critical / Major / Minor / Nit).
- Shamus runs polish loops:
  - One branch per finding cluster (a11y batch, edge-cases batch, contrast batch).
  - Each branch: ≤6 files, ≤200 lines, gates green, commit message cites the QA findings it addresses.
- Output: 1-N polish branches ready for Sky merge.

**Phase 6 — CHECK-IN (Morgan, end of cycle)**
- Aggregate: cycle commits, branches built, QA findings counts, what landed on main, what's still parked.
- Write `qa-reports/cycle-YYYY-MM-DD.md` (orchestrator-style).
- Write `2026-MM-DD_Project_Manager_Report.md` to Access Map Summarys folder.
- Create email draft to skylerhalisky@gmail.com with the 4-section spine + decisions list + merge recipes.
- Output: one briefing per cycle, traceable to every commit + every checkpoint.

## Cadence

- **1 cycle ≈ 3 features + QA + polish + briefing.** Self-paced; no fixed clock.
- **Every 3rd cycle is an "audit" cycle:** no new features. Instead: branch hygiene cleanup, LEARNINGS re-distillation, FEATURES.md backlog re-prioritization, decision-debt clearing pass.
- **Every cycle ends with at least one DECISION FOR SKY** if there's pending merge work — never let Sky's queue grow silently.
- **Bursts allowed.** When a feature is small (R8-style: 105 lines, no new lib), the cycle can ship more than 3. When a feature is big (e.g. clustering), the cycle ships fewer but goes deeper on QA.

## Gates summary (the rails)

| Between | Required to pass |
|---|---|
| Phase 1 (BUILD) → Phase 3/4 (CLEAN/TEST) | `npx tsc --noEmit` clean + `npx jest` green on every commit |
| Phase 3 (CLEAN) → Phase 5 (FIX) | No dead code surfaced; no protected-path touches |
| Phase 4 (TEST) → Phase 5 (FIX) | Lint clean + coverage holds; full suite green |
| Phase 5 (FIX) → Phase 6 (CHECK-IN) | Polish branches green; QA findings ≤ Minor severity remaining OR formally deferred |
| Phase 6 (CHECK-IN) → next Phase 1 | Sky has acknowledged the briefing OR a stop-condition (decisions blocking) is recorded |

## Hard "never" rules (inherited from Const. 1 + 5 + 9)

- Never modify `main` — only Sky merges.
- Never apply to live DB — migrations are FILES with rollback, not applied changes.
- Never email/Slack/notify Sky outside Morgan.
- Never handle/commit/print secrets.
- Never weaken RLS without Sky.
- Never bypass `--no-verify` or `--no-gpg-sign` without explicit Sky direction.
- Never act on a privacy-sensitive surface (location, disability data, auth) without Jordan's review surfacing via Morgan.
