## Optimizations made (branch perf/optionb-2026-10-23)

For each: cost → fix → expected impact.

1. **Welcome-first font gate + font-display swap** · Critical ·
   `src/lib/fonts.ts`, `App.tsx` (`cec00d4`) — every web face waited on all 8
   TTFs and rendered invisibly while they loaded → welcome gates on its own 3
   faces (`display`/`bodyMedium`/`label`), app screens still gate on all 8 so
   nothing swaps mid-render, and all 8 `@font-face` rules get
   `font-display: swap`. Expected: welcome usable ≈ 6.6 s → ≈ 3.5 s (candidate
   measured), QD-1 closes on re-measure. Native unchanged by construction.
2. **Preload the welcome's 3 faces from index.html** · High · `public/index.html`
   + MD5 guard test (`0683379`) — fonts downloaded after the JS executed →
   they now download alongside it. Blank gap ≈ 2.75 s → ≈ 50 ms (candidate).
3. **Gesture root + sign-in wall out of the web entry** · Medium ·
   `GestureRoot.*`, `SignInWall.*`, `App.tsx` (`b6a3487`) — RNGH (~192 KB) +
   hammer.js (~26 KB) + `SignInScreen` shipped to visitors who never see them
   → web resolves tiny platform stubs; native re-exports the same components.
4. **One lazy navigator chunk (QD-2 core)** · Critical · `AppNavigator.*`,
   `deferredScreens.*`, navigator + 3 screens, `App.tsx` (`7fc188f`) — the
   entry carried React Navigation + map stack + every screen → all of it moves
   to one on-demand chunk, prefetched at Skip/Continue so the download overlaps
   the remaining fonts (avoids the reviewed +2.2 s Skip regression), and the 4
   deferred screens ride INSIDE that chunk because Expo's `__common` chunk
   would otherwise load their shared code eagerly on the welcome page.
   Expected: entry script transfer ≈ 449 KB → ≈ 289 KB-ish (candidate measured
   275.8 KB including the severity refactor we deferred).
5. **Notifications SDK on demand (web)** · Low-Med · `loadNotifications.*`,
   `pushNotifications.ts` (`71cb43e`) — expo-notifications web shims sat in the
   entry → downloaded only from push-token/permission paths; native `require()`
   unchanged.
6. **Source maps in the deployment + audit builds (QD-3)** · High ·
   `vercel.json`, `lighthouse.yml` (`5f2deda`) — no maps existed at all →
   `--source-maps` in BOTH builds, identical on purpose (fixture-only maps must
   never green a check production fails).

## Proposals (NOT applied — need your review)

1. **First-launch Lighthouse budget** (preserved candidate's proposal):
   script transfer ≤ 300,000 B as `error`, `unused-javascript` demoted to
   `warning`. *Why it matters:* no honest build of this stack can pass
   `unused-javascript` at preset (≈77.6 KB of framework the welcome never runs;
   Lighthouse lists per-script at 20,480 B). *Steps:* review
   `artifacts/opus/review/budget-proposal/lighthouserc.proposed.js` on the Lexar
   volume; dry run: PR #33 449,481 B fails / candidate 275,778 B passes.
   *Risk:* changes the acceptance standard — explicitly NOT applied here because
   it would weaken a currently-honest failing assertion. Owner decision.
2. **Severity-palette extraction** (`c377bb0`+`e9c9842`+`4e1f3ff` in the
   preserved candidate): move `severityColor` out of `flags.ts` so the welcome
   doesn't import the data module. ≈13.8 KB transfer (≈75 ms slow-4G). Needs
   contract-owner sign-off on the `client-expectations.v1.json` line-field
   update. Steps + rollback documented in the integration package §6.1.
3. **Fix the CI "Performance Budget" job** (`.github/workflows/ci.yml`): remove
   its `|| true`/missing-`dist` fail-open and measure eager JS only. Risk: none
   to product; makes a dead gate real.

## Suggested next improvements (forward-looking)

- Make **first-launch cost a standing gate**: a tiny post-export script that
  records entry-chunk bytes + count of eager fonts into the QA report each run,
  so the 1x→100x creep (a new eager import in `App.tsx`) shows up in review
  instead of in a Lighthouse surprise.

  downloads at Skip; a second split (map libraries behind the Map tab) is the
  next structural win — profile first, it trades an extra round-trip for a
  smaller initial app chunk.
