## 2. CachedTileLayer — Offline tile a11y

`src/components/PlatformMap.web.tsx:94-163` (CachedTileLayer) · `175-190` (CachedTileLayerWrapper)

| Criterion | Verdict | Evidence |
|---|---|---|
| 1.1.1 Text alternative | PASS | `img.alt = ''` (line 110) — explicitly decorative, correct for map tiles |
| 1.4.1 Color not sole means | N/A | Tile rendering, not UI state |
| 4.1.3 Status messages | **FAIL (🟡)** | No live announcement when entering offline-served mode |

**Findings:**

- 🟢 **`img.alt = ''` is the correct WCAG 1.1.1 treatment.** Tile images are atomic raster fragments of a larger gestalt; alt text on each would generate hundreds of "image" announcements as the map pans. The aggregate map needs the alt, not the tiles.

- 🟡 **[MEDIUM] No screen-reader announcement when the user is offline and tiles are served from cache.** `src/components/PlatformMap.web.tsx:103-162` — when the network is down, `getCachedTile` silently returns the cached base64 data-URI and the user sees a fully-rendered map. A blind/low-vision user has no way to know the displayed data may be stale (cache TTL = 7 days per `tileCache.ts:14`). Per WCAG 4.1.3, status changes that affect the trustworthiness of displayed content should be programmatically determinable. **Propose:** add a `<View accessibilityLiveRegion="polite">` near the Map filter chips that reads *"Offline. Showing cached map tiles from last visit."* when `navigator.onLine === false`. This requires a connectivity hook (e.g., NetInfo on native, `online`/`offline` events on web) — **structural, propose-only.**

- 🟡 **[LOW] `MapContainer` has no accessible name or landmark role.** Leaflet's default `<div class="leaflet-container">` exposes no `aria-label` or `role="application"`. Keyboard users tabbing across the screen lose orientation. **Propose:** Dani + Shamus add a wrapping `<View accessibilityRole="region" accessibilityLabel="Map of accessibility flags">` to both `PlatformMap.tsx` and `PlatformMap.web.tsx`. (Existing concern; not new with CachedTileLayer but worth re-raising while the file is in focus.)

**Verdict: PASS for what CachedTileLayer DOES (tile fetch/cache logic does not regress a11y); PROPOSE-ONLY for what the map UX still LACKS.**

## 6. 🔴 SYSTEMIC ESCALATION — filterPill < 44pt touch target

`src/screens/MapScreen.tsx:1915-1920`

```ts
filterPill: {
  paddingHorizontal: 12,
  paddingVertical: 6,        // ← 6 + 12*1.2 + 6 ≈ 26.4pt
  borderRadius: radius.circle,
  backgroundColor: color.surfaceNeutral,
},
filterPillText: { fontSize: 12, color: '#333', fontWeight: '600' },
```

Used by Status, Category, Severity, Saved sets, AND now Distance filters on the Map filter panel — 5 chip rows of ~26pt-tall touch targets. **Fails WCAG 2.5.5 / 2.5.8.** Sighted users with tremor, large fingers, or one-handed grips will mis-tap.

This was first flagged 2026-05-24 in `qa-alex-r7-r15-2026-05-24.md` finding R7 (sort chip 36pt < 44pt, HIGH) and went unfixed. The Distance filter merging today reuses the same broken style — extending the regression surface.

**🔴 DO NOT silent-fix.** Per Const. Art. 12 single-change limit AND because bumping `paddingVertical` from 6 → 12 (to reach 44pt) reflows the entire filter panel — multiple chip rows may need to stack differently on small screens. Requires Dani (spacing token: `spacing.touchTargetSm`) + Shamus (layout review). **Escalate to Morgan → Sky.**
