HIGH-2 · Hidden comments — mockup gate

Run 2, Car 5. Visuals only. §SKY-6 already decided the pattern: a Settings “Hidden comments” list with per-item Unhide and Unhide All, built on the existing unhideContent / loadHidden primitives. Nothing below changes that — these are three row treatments and two placements for the bulk action. Pick one of each.

Already decided, not up for a pick. Storage stays untouched (hiddenContent.ts keeps storing bare ids, per your “on the existing primitives”). The list text therefore comes from a new fetchCommentsByIds() — a live re-fetch, not a stored snapshot. That choice is what makes row candidate C viable at all, and it is why every candidate needs a “no longer available” state.
The constraint driving all three. The hide list holds ids only — no text, no author, no flag. So a row can show real comment text only by re-fetching it, and a comment that was deleted server-side since you hid it cannot be shown. Every candidate must still let you unhide that row, or the entry becomes permanently stuck. That state is drawn in each mock.
