## How I scored (craft weighting)

- **impact** here is read through a craft lens too: does the fix *actually* land the disabled-user win end-to-end on the real RN-web/native surface (not a paper win that dies at the bundler, the falsy-zero, or a mount-timed live region)?
- **cohesion** rewards fixes that extend a ratified token/idiom and converge the material read; penalizes one-offs and integration seams.
- **ethos** rewards Deep-Field restraint + access-first distinctiveness executed to completion; penalizes signature framing that outruns the craft payoff, and rewards fixes whose reconciliation already closed the RN/Expo traps.
- Spread is deliberate. The reconciled FIX proposals that pinned the real RN-web hazard (persistent-mount live region, read/write abort split, falsy-zero, arbiter-on-light-tiles) earned back trust; the ones that are pure mechanical law-extension are the safest craft on the board; the L-tier integrations carry real (well-scoped) risk.

**S6 — honest 44pt zoom buttons (Signature, reconciled).** impact 5 / cohesion 4 / ethos 4. **S8 — one editorial header family (Signature, reconciled).** impact 3 / cohesion 5 / ethos 5. The strongest chrome-cohesion win — closes the "two kits stitched together" seam on every tab switch. **S9 — mount the a11y engine on web (Signature, L, CRITICAL).** impact 5 / cohesion 5 / ethos 5. Craft thesis of the whole audit: the best-engineered subsystem is one RN-web dialect gap (0.21.2's `createDOMProps` reads only flat `aria-*`, drops the nested `accessibilityState` object) from working where guests live. The fix is *additive beside* existing props (flat `aria-*` maps to the same native state AND the DOM), routes announcements through a rendered `aria-live` node (NOT the dead `announceForAccessibility`), and correctly notes plain `disabled` already translates. L-tagged for breadth (~30 sites + shim + shared object), each edit mechanical/low-risk — the honest "wide surface, re-verify every touched screen" is the right durability posture. No native regression by construction.

**S10 — submit confirmation banner (M, reconciled).** impact 4 / cohesion 4 / ethos 4. The reconciliation is the entire craft story and it is correct on two hard RN-web facts: (1) `FlashBanner` returns `null` until it has text, i.e. it mounts *with* text — the exact case SRs drop — so it must become a persistent-mounted `aria-live` whose text *mutates* (mirroring the always-mounted severity echo line that already works), and (2) FlashBanner only mounts in `SignedInArea`, so the anon-web cohort — S10's whole audience — never sees it unless the region is lifted above the session branch. Optional camera-center gated on reduced-motion. Solid, durable, but a supporting act to S5 (the finish line of a flow S5 first has to unblock), so 4s.

**S11 — data-layer timeout + "still trying" (Signature, reconciled).** impact 4 / cohesion 4 / ethos 4. The read/write abort split is the make-or-break craft call and the reconciliation nailed it: hard-aborting a *write* at the threshold could orphan a server-committed insert into a false "still trying" → doubt-resubmit → duplicate flag under the anon 5/day limit. Scoping the hard abort to reads, escalating writes via overlay (or pairing abort with idempotency), and adding a guard test that a post-threshold write does NOT double-insert is exactly right. Mirrors the existing GPS race shape (no new pattern, zero new pollers). Signature framing is slightly generous for what is fundamentally a robustness fill of an unbounded middle — hence 4s not 5s — but it closes R1's stated #1 danger-path fear.

**S12 — web reduce-motion camera parity (M).** impact 4 / cohesion 4 / ethos 4. The highest-value *correctness* fix in its cluster and a genuinely instructive craft catch: `flyTo(…, {duration: reducedMotion ? 0 : 0.6})` — Leaflet treats `0` as falsy → distance-based default, so the RM user gets the *biggest* motion in the app. The fix (`{animate:false}` → short-circuits to instant `setView`) is the correct Leaflet idiom, and threading `reducedMotion` into `ClusteredMarkers` (which never receives it) closes the sibling leg. The required guard test (assert `flyTo` called with `animate:false` under RM) is precisely the test whose absence let the trap ship — strong durability. Confirmed WCAG 2.3.3 fix; scoped, no new abstraction.

Impact 5: it makes the trust engine (verify/resolve/reject) operable by blind users on the surface built for it — currently sighted-only on native. Honestly device-gated for confirmation (NEEDS-SKY-DEVICE), which is why cohesion/ethos sit at 4: the code fix is sound and lands the web nested-`<button>` fix in-harness, but the headline native win awaits the one EAS build.
